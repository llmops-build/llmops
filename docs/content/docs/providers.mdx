LLMOps routes requests to LLM providers through an OpenAI-compatible gateway. Providers are configured in code via the `providers` array or auto-detected from environment variables.

---

## Provider Configuration Options

### Common Fields

All providers support these base options:

| Field       | Description                                  |
| ----------- | -------------------------------------------- |
| API Key     | Your API key for the provider                |
| Custom Host | Override the default API endpoint (optional) |

---

## Major Cloud Providers

### OpenAI

Access GPT-4, GPT-3.5, and other OpenAI models.

| Field           | Description                       |
| --------------- | --------------------------------- |
| API Key         | Your OpenAI API key               |
| Organization ID | OpenAI organization ID (optional) |
| Project ID      | OpenAI project ID (optional)      |

### Azure OpenAI

Access OpenAI models hosted on Azure.

| Field               | Description                                               |
| ------------------- | --------------------------------------------------------- |
| API Key             | Your Azure OpenAI API key                                 |
| Resource Name       | Azure resource name                                       |
| Deployment ID       | Azure deployment ID                                       |
| API Version         | Azure API version (e.g., `2024-02-15-preview`)            |
| Authentication Mode | API Key, Entra ID, Managed Identity, or Workload Identity |

### Google Gemini

Access Gemini models via Google AI.

| Field   | Description         |
| ------- | ------------------- |
| API Key | Your Google API key |

### Google Vertex AI

Access Gemini and other models via Google Cloud Vertex AI.

| Field                | Description                            |
| -------------------- | -------------------------------------- |
| Project ID           | Google Cloud project ID                |
| Region               | Vertex AI region (e.g., `us-central1`) |
| Service Account JSON | Service account credentials JSON       |

### AWS Bedrock

Access Claude, Llama, and other models via AWS Bedrock.

| Field                 | Description                                   |
| --------------------- | --------------------------------------------- |
| AWS Access Key ID     | AWS access key ID                             |
| AWS Secret Access Key | AWS secret access key                         |
| AWS Region            | AWS region (e.g., `us-east-1`)                |
| Session Token         | AWS session token (for temporary credentials) |

## Supported Providers

### OpenAI-Compatible (Auto-Detected)

These providers speak the OpenAI wire format and are auto-detected when their API key environment variable is set:

| Provider      | Key             | Env Var                |
| ------------- | --------------- | ---------------------- |
| OpenAI        | `openai`        | `OPENAI_API_KEY`       |
| Google        | `google`        | `GOOGLE_API_KEY`       |
| Mistral AI    | `mistral-ai`    | `MISTRAL_API_KEY`      |
| Groq          | `groq`          | `GROQ_API_KEY`         |
| Together AI   | `together-ai`   | `TOGETHER_API_KEY`     |
| Fireworks AI  | `fireworks-ai`  | `FIREWORKS_API_KEY`    |
| DeepSeek      | `deepseek`      | `DEEPSEEK_API_KEY`     |
| Perplexity AI | `perplexity-ai` | `PERPLEXITY_API_KEY`   |
| OpenRouter    | `openrouter`    | `OPENROUTER_API_KEY`   |
| xAI           | `x-ai`          | `XAI_API_KEY`          |
| Cerebras      | `cerebras`      | `CEREBRAS_API_KEY`     |
| SambaNova     | `sambanova`     | `SAMBANOVA_API_KEY`    |
| AI21          | `ai21`          | `AI21_API_KEY`         |
| DeepInfra     | `deepinfra`     | `DEEPINFRA_API_KEY`    |
| Nebius        | `nebius`        | —                      |
| Novita AI     | `novita-ai`     | —                      |
| Moonshot      | `moonshot`      | —                      |
| Jina          | `jina`          | —                      |
| Inference.net | `inference-net` | —                      |
| Upstage       | `upstage`       | —                      |
| NScale        | `nscale`        | —                      |
| Lemonfox AI   | `lemonfox-ai`   | —                      |

### Divergent (Requires Dedicated Adapter)

These providers do **not** use the OpenAI wire format. They require a dedicated gateway adapter. Until one is available, configure them explicitly with a custom adapter via `config.adapters`:

| Provider     | Key               | Status                |
| ------------ | ----------------- | --------------------- |
| Anthropic    | `anthropic`       | Adapter pending       |
| Cohere       | `cohere`          | Adapter pending       |
| AWS Bedrock  | `bedrock`         | Adapter pending       |
| Google Vertex| `vertex-ai`       | Adapter pending       |
| Azure OpenAI | `azure-openai`    | Adapter pending       |
| Azure AI     | `azure-ai`        | Adapter pending       |
| Replicate    | `replicate`       | Adapter pending       |
| Stability AI | `stability-ai`    | Adapter pending       |
| Fal AI       | `fal-ai`          | Adapter pending       |
| Segmind      | `segmind`         | Adapter pending       |

> **Note:** The auto-detection list only includes providers that have bundled metadata and a static base URL. Providers requiring region, resource, or deployment configuration (Azure, Bedrock, Vertex) are excluded.
